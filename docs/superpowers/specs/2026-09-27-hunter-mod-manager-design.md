# 设计规格：怪物猎人三作 Mod 管理器

- 日期：2026-09-27
- 状态：已批准范围，实施中；本规格不作为完成验收的证据。
- 目标平台：Windows x64；首要支持 Steam 安装。

## 目标与非目标

提供便携式图形界面，让用户对已识别的文件型 Mod 执行导入预览、启用和停用。支持目标为《Monster Hunter: World》（MHW）、《Monster Hunter Rise》（MHR）和《Monster Hunter Wilds》（MHWs）。输入压缩格式为 ZIP、RAR、7Z。

首版不运行压缩包内的 EXE/MSI/脚本安装器，不自动部署 PAK，不承诺自动处理任意未知目录结构，不代表一次文件复制即证明游戏实际加载成功。暂不提供加载顺序管理。

## 用户流程

1. 用户选择游戏并选择/拖入压缩包，或定位游戏目录；目录识别需允许手动指定并验证可执行文件或游戏标记。
2. 管理器先检查压缩包条目和路径，不执行其中程序，不落地到游戏目录。
3. 识别 `nativePC`、`natives`、`reframework` 等锚点；多版本包要求用户选一个版本。识别不充分时要求逐项映射或说明无法处理。
4. 展示目标路径、目标文件、覆盖对象、冲突、前置条件、PAK/安装器等不支持项目，用户确认导入。导入仅保存包和记录，不立即部署。
5. 用户勾选 Mod 才部署；取消勾选时回滚该 Mod 的文件。与其他已启用 Mod 争用路径时先报告冲突；如支持替换，必须在同一事务里停用旧 Mod 并启用新 Mod。

## 文件和包识别

压缩包读取层应在抽取前拒绝：绝对路径、`..` 路径穿越、驱动器/UNC 路径、链接条目、大小写不敏感的重复目标名和加密条目。检查条目数、解压总量和可用空间，以避免不受控的写入。RAR/7Z 的解析由最终选定且许可确认的依赖实现；如果运行环境缺少解析能力，应明确提示，不得伪称支持。

映射器只把受支持的锚点转换为目标游戏的相对路径。模糊包结构不得静默猜测。多个候选文件树要用户选版本。PKG 中含有独立安装器时仅列出并解释。

PAK 边界：Rise/Wilds 中发现 `.pak` 时可在预览中分类并说明首版不自动安装；不得声称已校验编号规则或卸载安全性。

## 部署、冲突与回滚

安装记录至少保存游戏根目录、来源压缩包哈希、所选包内版本、启用状态和目标相对路径/内容哈希。所有目标路径规范化后必须留在已验证的游戏根目录下。

部署前进行冲突解析、空间检查和目标状态校验。目标为此前不存在的文件时记录由管理器创建；目标已有文件时保留可恢复备份。临时写入后原子替换（若平台允许），再核验落盘哈希。事务日志须支持识别不完整操作并在重启后恢复或要求用户选择恢复方式。

停用时：对管理器新建且内容仍等于管理记录的文件可删除；对有备份文件的目标只有在当前内容仍是管理器部署版本时恢复备份。若哈希不符，说明目标受到外部修改，不能覆盖或删除，应保留现场并提示人工处理。不得以递归清理 `nativePC`/`natives` 目录来卸载单个 Mod。用户现有内容属于保留数据；尤其 MHW 中已存在的 `nativePC` 文件须逐文件保护。

## 状态与位置

计划使用 `%LOCALAPPDATA%\HunterModManager` 存储应用状态、导入压缩包、事务记录和备份。状态须足以在重启后重建 UI，并检测待恢复事务。改变游戏目录前应明确原安装记录关联的根目录，不将旧记录应用到新目录。

## 提权与信任边界

主 UI 以普通权限运行，保留资源管理器拖放体验。只有目标目录拒绝写入时才考虑独立提权辅助进程。辅助进程必须重新验证调用参数、游戏根路径、目标相对路径与包内容，拒绝目录逃逸；不得把管理员权限交给包中代码。提权实现尚需结合代码结构和 Windows 实际行为验证。

## 游戏和前置规则

### World

- 自动管理经确认的 `nativePC` 文件树和明确规则的根目录组件。
- 提供 Stracker’s Loader 检查；前置组件由用户下载并导入本地包，经同一预览和备份流程部署。
- 不以目录存在推断加载器完整可用，也不覆盖用户现有 `nativePC` 内容而不备份。

### Rise

- 自动管理 REFramework 脚本与插件目录。
- `natives` 散文件只有在相关加载器/配置条件已经确认时才允许标为可运行部署；否则显示所需前置与状态。
- REFramework 从 [官方 GitHub releases](https://github.com/praydog/REFramework-nightly/releases/) 获取。FirstNatives 等 Nexus 包由用户下载，再导入本地压缩包；不得自动登录或抓取需账户的文件。

### Wilds

- 自动管理 REFramework 脚本与插件目录。
- `natives` 散文件只有 Loose File Loader 等要求成立时才部署，并检查可能的游戏设置；需要游戏内操作时明确标为待办。
- REFramework 从[官方 GitHub releases](https://github.com/praydog/REFramework-nightly/releases/)获取。

所有游戏均按 REFramework 官方文档选择文件，非 VR 安装只布置官方要求的 `dinput8.dll`；不将完整包展开。具体官方文件布局可能变化，实施时需核对当前发布页和说明，不把推断写成已验证事实。

## 便携发布与许可

目标为 .NET 10 WinForms Windows x64 自包含发布，交付解压即运行的 ZIP。发布前需核实单文件设置、运行时包含、实际产物启动、许可与 SHA-256 清单。项目如果使用 7-Zip 相关组件，必须根据具体组件和版本提供相符的许可、版权声明及源码义务说明；参考 [7-Zip 官方许可说明](https://www.7-zip.org/license.txt)。不能把格式兼容与许可证等同，也不能在未实际打包前声称已包含 7-Zip。

## 验收检查点

- 构造 ZIP/RAR/7Z 测试包，检查普通结构、多版本、恶意路径、重复路径、加密包、损坏包和不支持项。
- 在临时模拟目录验证首次部署、覆盖前备份、取消启用还原、冲突交换、外部修改拒绝和事务中断恢复。
- 通过 UI 检查三款游戏识别、拖放、预览、前置状态及用户可理解的错误提示。
- 对 World/Wilds 的本机安装只做只读目录预览；Rise 当前没有确认可用的实装目录，因此需用模拟目录验收，并且不宣称游戏内测试。
- 构建 Windows x64 自包含包，检查启动和依赖文件、许可及哈希清单。

以上均为验收计划；每项只有在记录实际命令、结果和边界后才能标为通过。
